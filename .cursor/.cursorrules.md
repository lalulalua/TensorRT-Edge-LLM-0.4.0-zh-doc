# Workflow & Documentation Guidelines
在执行任何代码注释和文档编写任务时，必须严格遵循以下工作流：

1. **全局代码注释**：
   - 深入遍历所有子文件夹和源代码文件。
   - 对核心数据结构、内存管理（如显存分配、指针传递）和算子调度逻辑添加精确的中文注释。
   - 揭示代码背后的工程意图，而非简单的逐句翻译。

2. **README 自动构建与本地化机制**：
   - 自动检测：扫描所有层级的文件夹，只要该文件夹内包含 `CMakeLists.txt` 文件，就必须为其配备一个说明性的 `README.md`。
   - 重命名覆盖：如果目标文件夹内已经存在原生的 `README.md`，**必须先将其重命名为 `README_en.md`**，然后再新建一个全新的 `README.md`。
   - 纯中文输出：新建的 `README.md` 内容必须完全是中文，详细说明该目录的构建方式（CMake 配置解析）、模块功能和依赖关系。

3. **数据流流程图绘制 (Mermaid)**：
   - 在生成的 README 或关键代码注释区，必须使用 **Mermaid 语法**绘制架构与数据流动流程图。
   - **主流程图**：展示该模块端到端的数据输入、处理（如 Pre-processing, Inference, Post-processing）到输出的完整链路。
   - **子流程图**：针对复杂的子模块（如特定的解码策略或混合精度算子内部流转），按需绘制详细的子流程图，确保系统变量和数据流转的逻辑一致性。

# Translation Guidelines
在涉及本项目的所有中英文档翻译和编辑时，必须严格遵守以下规则：

1. **核心原则**：
   - 保持专业、准确、干练的技术文风。
   - 拒绝“机翻腔”，使用符合中文开发者阅读习惯的句式（如：多用动宾短语，少用被动语态）。
   - 必须保留所有的 Markdown 标签、YAML 配置、图片内链和锚点。

2. **专业术语对照表 (Terminology)**：
   - 遇到以下专有名词时，严禁生硬翻译，请按要求处理：
   - Inference Engine -> 推理引擎
   - Quantization -> 量化 (如 AWQ, QAT 等缩写直接保留英文)
   - CUDA / TensorRT / FlashAttention -> [保持英文原写，注意大小写]
   - Activation Buffer -> 激活缓存 / Activation Buffer
   - Operator Fusion -> 算子融合
   - **engine 文件** -> 当特指 TensorRT 序列化生成的模型文件时，必须使用 "engine"（例如："加载 engine 文件"），**绝对禁止**直接翻译为“引擎”。

3. **代码块规范**：
   - 绝不翻译代码块中的代码逻辑、变量名和函数名。
   - 仅当原英文注释过于晦涩或描述关键算法逻辑时，才将其翻译或扩写为详尽的中文注释。
